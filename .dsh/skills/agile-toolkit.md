# agile-toolkit — 能力脚本用法手册（形态 C，按需加载）

> **本 skill 只写"怎么用"，不写"何时必须用"。** 触发规则在契约里（硬约束）——见「检查契约」的「工具触发规则」一节与「写作契约」的写作准则（两契约均在 `profile.yaml` 的 `paths.contracts` 下）。
>
> **脚本本体不在本 skill 里**，在 `profile.yaml` 的 `paths.tools`（**本手册只讲随 `.dsh/` 交付的那 18 支**）。搬进 skill 会与分发器（仓库根 `dev/sync-tools.mjs`）形成第二套副本，引发"副本漂移"。本 skill 是**指引**，不执行任何东西。

## 通用约定

- **全部零模型参与**——纯机械判定，结论可重跑、可复现。
- **以退出码表达结果**：`0` = 通过，非 `0` = 不通过。批量类会给出逐项明细。
- **`--dry-run` 优先**：凡修改类工具先跑 dry-run 看清单，再真跑。
- **路径基准**：所有工具以**当前工作目录**为基准，需在项目根执行。

## 一、判据定义库（**唯一定义处，不要另行实现**）

| 脚本 | 用途 | 关键点 |
|---|---|---|
| `lib-traces.mjs` | **修订痕迹（D10）判定的唯一定义处** | 别处判定修订痕迹必须引用它，不得重写正则 |
| `lib-numfingerprint.mjs` | **数值指纹的唯一定义处** | 端口/字节数/时间戳/PID/epoch/SHA256/inode 的提取规则 |
| `lib-lines.mjs` | **行数口径的唯一定义处** | `countLines()` / `measure()`。**任何工具要行数必须 import 它，不得自行实现**——实测三种常见实现量出三个数（见 `.dsh/tests/lib-lines-check.mjs`） |

> **这三支是"判据的判据"**——改了它们等于改了所有下游工具的判定口径。修改须走架构师（契约与判据所有者）。

## 二、零丢失核对（**每次修订正式文档后必跑**）

| 脚本 | 用途 | 何时跑 | 已知假阳性 |
|---|---|---|---|
| `verify-rewrite.mjs` | **改前 vs 改后的零丢失校验器**（体量、标识符留存、数值指纹留存、修订痕迹、结构、超长行六项） | **每次修订 `docs` 下正式文档后必跑** | **只看第 2b 节"真缺失"列**；工具已内置"真缺失/正则伪影"分类，**伪影不算缺失** |
| `num-diff.mjs` | 改前 vs 改后的**数值指纹全量对撞**（比 verify-rewrite 更细） | 需要逐个数值确认去留时 | 同上 |
| `measure-netgrowth.mjs` | 「净增长 ≤ 0」闸门的度量 | 回环期每轮 | — |
| `measure-section-growth.mjs` | 「净增长」的**逐节对账** | 需定位是**哪一节**在涨时 | — |

> **参数名仍叫 `--original` / `--rewrite`**（历史命名）：它们指**改前稿 / 改后稿**，
> 与"整体重写"无关。**常规修订同样适用**——这正是本条保留在契约里的原因。

## 三、缺陷检测（内容层）

| 脚本 | 用途 | 备注 |
|---|---|---|
| `detect-gaps.mjs` | 「**结论缺失型**」检测 | — |
| `check-03-claims.mjs` | 只问"**正文有没有那个结构**"，不比对旧稿 | 不测"内容对不对" |
| `selfcheck-10q.mjs` | 架构师交付前自查 10 问的机械化部分 | 契约里另有 10 问全文，人读部分不可替代 |
| `table-integrity.mjs` | **表格结构完整性审计**——内容层判据，与数值判据互补 | — |
| `row-duplication.mjs` | 表格行重复/被压成列表项 | **只在改前没有、改后有时才是缺陷** |
| `find-empty-table-body.mjs` | **表体被删**扫描 | — |
| `analyze-flatten.mjs` | 诊断"表格被拍扁成 `- \|` 列表项" | 只诊断，不修改 |

## 五、辅助与同步

| 脚本 | 用途 |
|---|---|
| `ref-existence-check.mjs` | 引用存在性检查 |
| `REGISTRY.md` | 能力脚本登记册（**生成物**，列出全部在役脚本及其用途）|

> **登记册怎么重生成**：这是**模式仓库的维护动作**，生成器在仓库根 `dev/`（不随交付件走）：
> `node dev/gen-tool-registry.mjs` 重写登记册；`--check` 只校验它是否与真实集合一致（不写盘）。
> **消费项目不需要做这件事**——登记册随 `.dsh/` 一起来。

## 六、门禁与台账

| 脚本 | 用途 | 关键点 |
|---|---|---|
| `code-gate.mjs` | **代码门禁**（QA 的 C2–C6）：`--scope <变更文件...>` | **先读 `profile.yaml`**：未声明的技术栈报 **`N/A` 而不是 FAIL**。**C1 判不了形式，保留人工**；**脚本通过 ≠ 质量合格**。`--json` 只吐 JSON |
| `ledger-check.mjs` | **运行台账的格式校验**（P3c） | 只验格式（列数/日期/链 id/FAIL 分布可解析），**不验内容真伪**——工具的边界必须说清 |
| `profile-ref-check.mjs` | **占位符解析核对**：契约里每个双花括号占位符（形如 `{{paths.docs}}`、`{{tech_stack.build}}`）是否都能在 `profile.yaml` 里解析 | 未声明 ⇒ **FAIL**；只声明在注释骨架里 ⇒ WARN。**必要原因**：占位符解析不了时契约不报错，它会带着原文的双花括号**继续跑并照常给出判定**——比硬编码更隐蔽（硬编码至少是个真值，只是不对；未解析的占位符是一句没有意义的话） |

## 七、使用纪律

1. **只用不改**：这些脚本是**判据**，判定口径的修改属契约变更，归架构师。
2. **不合并**：18 支是**独立可跑的判据**，各自退出码有意义；合并会破坏"哪条判据失败"的可观测性。
3. **不复制进 skill**：见文首。
4. **假阳性要登记**：发现新的正则伪影，登记到本 skill 的"已知假阳性"列，而不是就地放宽判据。
